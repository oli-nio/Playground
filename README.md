# FORMIKAT Playground

> **Repository role: PRESENTATION / DEMO / EXPERIMENT — NON-CANONICAL**
>
> The current FORMIKAT OS architecture, contracts, gates and operational state live in **`oli-nio/Formikat-OS`**.

This repository is a publishing and experimentation surface for prototypes, web pages, visual material, pitches and demos. Content here may intentionally simplify, visualize or speculate beyond the current implementation.

## Master repository map

- **`Formikat-OS`** → CANONICAL CURRENT: architecture, contracts, gates, operational state and accepted implementation decisions.
- **`formikat-research`** → research evidence, historical reproduction, reviews, advisor material and experiments.
- **`formikat-skills`** → accepted reusable Formikat skills.
- **`formikat-ideas`** → ideas/hypotheses.
- **`IB-Digital-Innovation`** → funding/program-specific work.
- **`formikat-workflow-architecture-redteam-2026-08-19`** → frozen historical snapshot.
- **`Playground`** → this repository: presentation/demo/experiment surface.
- **`formikat-rnd-test`** → technical tests only.

## Interpretation rule

`pitch/demo representation ≠ architecture decision ≠ implemented capability ≠ proven operational state`

For example, a journey, diagram or feature shown in a pitch page can communicate a target vision without proving that the capability is already implemented.

## Agent instruction

Use this repository for presentation context and prototypes. If you need to determine whether a capability really exists, what the current architecture is, or what work is authorized, consult `oli-nio/Formikat-OS` and its evidence links instead of inferring from a demo.

If this repository conflicts with canonical OS state, the conflict should be fixed in the presentation or explicitly marked as future/vision content; the demo must not silently redefine the OS.
